How OpenGeoStreams is built

A guided tour of the opengeostreams package: what each module does, which functions it contains, and which part of the water-quality dashboard each one produces.

Python library & server JS browser dashboard HTTP endpoints External services & files

1. The big picture

OpenGeoStreams is a Python library that happens to ship with a dashboard. Every chart, network match and interpolation surface is computed in Python. The browser only draws results and runs a few light client-side rules.

You can use it in two ways, and both go through the same code:

As a library (notebooks, scripts)

import opengeostreams as ogs
ds = ogs.load_csv("river.csv", rows="all")
ds.plot_trend(parameter="BOD")      # Plotly figure
ds.channel_network()                # drain/river matching
ds.plot_map("map.html")             # Folium map

As a dashboard (browser)

ds.dashboard()                      # from Python, or
python -m opengeostreams.server     # standalone
# → http://127.0.0.1:4173

The server calls the same RiverDataset methods and sends their output to the browser as JSON.

Key ideaThe server does not render images. Python builds each chart as a Plotly figure specification (JSON describing traces and layout). The browser receives that JSON and calls Plotly.react() to draw it. The map is different: it is built in the browser with Leaflet from raw data (stations, GeoJSON channel lines, interpolation grid values).

network.py

Python850 lines · drain/river matching

Answers two questions: which drain or river is each station on? and in what order do they sit, upstream → downstream? It uses geopandas and shapely on the India-WRIS channel network. The result is a geometric approximation, not a hydrological model.

Drain/river lines on mapStream: drain selector & groupingChannel summaryRiver-following interpolation

The algorithm (as documented in the module)

  1. Assign a channel to each station, in priority order: (a) a name column in the file (Water Body, Drain …); (b) a water-body name parsed from the station label ("HUDIARA DRAIN AT …"), fuzzy-matched to a nearby line; (c) the nearest network line within max_distance_km (default 2 km). Stations with none of these are reported as unassigned.
  2. Build channels. Connected lines with the same name are joined into one channel. Endpoints within 30 m are treated as one graph node.
  3. Find the outlet. This is the lowest end by terrain elevation (Open-Meteo), preferring an end that joins a differently named line (a confluence). Offline, it falls back to confluence detection and line direction. The method used is reported for each channel.
  4. Order stations by distance along the channel to the outlet (Dijkstra over the line graph). The farthest station is the most upstream. U/S / D/S labels break near-ties.

elevation.py

Python62 lines · optional connector

A single function, fetch_elevations(frame, project=None). It samples the Copernicus GLO-30 DEM (COPERNICUS/DEM/GLO30_2024_1) at each unique station through Google Earth Engine, in batches of 500 points. It returns a DataFrame of Location, Latitude, Longitude, elevation_m, status, source.

It needs pip install "opengeostreams[earthengine]", a one-time ee.Authenticate(), and the environment variable OPENGEOSTREAMS_EE_PROJECT set to a Cloud project ID. Otherwise it raises a ValueError with setup instructions, which the panel displays.

Station elevation panel
Two different elevation sourceselevation.py (Earth Engine, opt-in) feeds the elevation panel. network.fetch_point_elevations (Open-Meteo, no account needed) is used only internally to decide which end of a channel is downstream.

server.py

PythonHTTP604 lines · web server

A standard-library ThreadingHTTPServer (no Flask or FastAPI) with one handler class, DashboardHandler, that routes on the path with plain if statements. It keeps imported datasets in memory, turns library output into JSON, and serves the static frontend from pipeline.ROOT.

All endpointsUpload & combineFigure cache

Server state

create_server() attaches three attributes to the server object:

  • server.datasets: a dict mapping a random UUID to a dataset entry
  • server.active_dataset: the UUID currently shown
  • server.dataset_lock: guards both of the above

A dataset entry, created by dataset_entry(), holds the RiverDataset, its file name, an LRU figures cache, and one lock per expensive operation (one per chart kind, plus interpolation, elevation and network).

dashboard_assets/

No build step and no framework: plain scripts loaded in this order at the bottom of index.html:

Leaflet (unpkg)  →  /plotly.min.js  →  /dashboard-data.js  →  ui.js  →  app.js  →  inline script

/dashboard-data.js is generated per request by the server. It assigns the active dataset's payload to window.NCHOE_DASHBOARD_DATA. When the user uploads or switches files, the page simply reloads (location.replace('/?data=…')) so the new payload loads.

index.html

Markup for every panel, plus an inline script that handles the non-chart server calls:

  • upload form → /upload-csv
  • file switcher → /datasets, /select-csv

ui.js

The dashboard shell. It knows nothing about water quality. It reads state through window.OGS and listens for ogs:ready.

  • open/close/resize panels and the drawer
  • theme toggle, toasts, basemap popover

app.js

The analysis engine of the page. One central state object (selectedLocation, selectedParameter, selectedPeriod, selectedYear, selectedUseCase, boxplotGrouping, streamChannel, baseMap). Every interaction updates it and redraws the affected panels.

6. Request walkthroughs

Four end-to-end traces through the whole stack. Together they cover every module.

A. Uploading a CSV

  1. User drops a file. The inline script in index.html POSTs it to /upload-csv?rows=all.
  2. DashboardHandler.handle_upload → extract_uploaded_csv → process_uploaded_csv. Non-CSV formats go through convert_upload_to_csv / normalize_uploaded_table first.
  3. dataset.load_csv → RiverDataset._set_data runs pipeline.standardize_rows → merge_duplicate_locations → validate_rows → build_dashboard_data.
  4. The server stores the dataset under a new UUID, makes it active, and calls warm_network(), which starts drain/river matching on a background thread.
  5. The response carries summary. The browser reloads, fetches the new /dashboard-data.js, and app.js boots: markers, parameter tabs, station list and filters all come from that payload.

B. Clicking a parameter → trend chart

  1. A parameter button click sets state.selectedParameter and calls refreshViewsForParameterChange().
  2. renderLibraryFigure("trend", …) aborts any in-flight trend request and fetches /api/figure?id=…&kind=trend&parameter=BOD&location=…&year=all.
  3. build_figure checks the figure cache. On a miss it copies the dataset, maps names with pipeline.parameter_family, filters location, year and month, then calls view.plot_trend().
  4. plots.trend_figure adds a Scatter per station. For precipitation it uses rainfall rows from the CSV, or calls _weather_precipitation → server.fetch_weather_data → Open-Meteo archive.
  5. The figure → to_json() → cached → returned. app.js merges its themed chartLayout() and calls Plotly.react(), then installTrendHover() attaches the custom tooltip.

C. The interpolation layer on the map

  1. app.js loadInterpolationData() fetches /api/interpolation once per dataset (one shared promise).
  2. ensure_interpolation first waits for ensure_network. The network was already warming since upload.
  3. RiverDataset.interpolate → _network_river_mask → network.river_corridor_mask rasterises matched channels onto the 192×192 grid.
  4. pipeline.build_interpolation_data builds an all-years surface and one per year for every parameter family, using ordinary kriging only inside the mask.
  5. The browser picks the surface for the current parameter/year (getInterpolationSurface), converts it to a PNG via an off-screen canvas (buildInterpolationImage), and lays it on the map with L.imageOverlay. Switching parameter needs no new request.

D. Stream view for a single drain

  1. loadChannelNetwork() fetches /api/network, fills the drain <select>, draws GeoJSON lines, and chooses the drain of the selected station.
  2. renderLibraryFigure("stream") requests /api/figure?kind=stream&channel=<channel-id>.
  3. build_figure reuses the cached network (view._channel_network) and calls plot_stream(channel=…).
  4. plots._channel_order lists that channel's stations upstream → downstream, including "D/S of" stations on the receiving river. stream_figure pivots mean values into a station × year heatmap in that row order.
  5. app.js sizes the chart, pages it (buildStreamPages), and renderChannelSummary() shows length, outlet method and the latest-value profile along the drain.

7. Caching and threads

Network matching and kriging can take seconds, so results are computed once and reused at several levels.

Each dataset entry has its own locks: figure_lock, one chart_locks[kind] per chart type, plus network_lock, interpolation_lock and elevation_lock. Two browser tabs asking for the same slow result wait for one computation instead of starting two. Different chart kinds can still build in parallel.

8. Using it from Python

Everything the dashboard shows is available without the browser.

import opengeostreams as ogs

ds = ogs.load_csv("Datasets/consolidated_dataset.csv", rows="all")
print(ds.summary["locationCount"], "stations")
ds.head()
ds.describe("BOD")
ds.coordinate_conflicts()                      # stations with inconsistent positions

# Drain / river matching (needs opengeostreams[network])
net = ds.channel_network()
ds.assign_channels()                           # one row per station

# Charts: the same figures the dashboard shows
ds.plot_trend(parameter="BOD", location="N-CHOE D/S")
ds.plot_distribution(parameter="BOD", grouping="month")
ds.plot_stream(parameter="BOD", channel=net["channels"][0]["id"])
ds.plot_stream(parameter="BOD", group_by_channel=True, save_path="stream.html")

# Interpolation
_, info = ds.interpolate()
ds.plot(parameter="BOD", year=2023)
ds.plot_map("bod_map.html", parameter="BOD")   # Folium map, opens in browser

# Combining files
merged = ogs.concat([ds, ogs.load_csv("other.csv")], name="combined.csv")

# Launch the dashboard preloaded with this dataset
server = merged.dashboard()                    # http://127.0.0.1:4173
